How the audit works

Three passes, all local to your browser tab.

01

Paste or upload

Drop in a file or paste a snippet. Nothing leaves your machine — there's no upload endpoint, no server side to this at all.

02

Pattern audit

Each line is checked against known query-building idioms — f-strings, template literals, concatenation, .format() — and cross-checked against nearby parameterization markers to cut false positives.

03

Remediation

Every finding ships with the parameterized rewrite for that language, so the fix is a copy-paste away, not a research project.

Detection coverage

The same failure mode, five syntaxes. ParamCheck recognizes all of them.

Python — f-string / format interpolation
Vulnerable
cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")
Fixed
cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
JavaScript / Node — template literal interpolation
Vulnerable
db.query(`SELECT * FROM users WHERE id = ${userId}`)
Fixed
db.query("SELECT * FROM users WHERE id = $1", [userId])
PHP — superglobal concatenation
Vulnerable
$sql = "SELECT * FROM users WHERE id = " . $_GET['id'];
Fixed
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->execute(["id" => $id]);
Java — Statement concatenation
Vulnerable
stmt.executeQuery("SELECT * FROM users WHERE id = " + userId);
Fixed
PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE id = ?");
ps.setInt(1, userId);
C# — SqlCommand concatenation
Vulnerable
cmd.CommandText = "SELECT * FROM users WHERE id = " + userId;
Fixed
cmd.CommandText = "SELECT * FROM users WHERE id = @id";
cmd.Parameters.AddWithValue("@id", userId);

Why this stays static

Scope is a design decision here, not a disclaimer.

  • No network calls, ever. ParamCheck never opens a socket. The entire audit runs in JavaScript in your tab.
  • No target to authorize. There's nothing to point at a URL, so there's no question of scope or permission to sort out first.
  • Safe against any codebase. Paste code from a repo you don't control, a tutorial, or a take-home — the tool only ever reads text.
Known limitation Detection is line-level pattern matching across a few common query-building idioms — not full AST or taint analysis. It won't trace a query string built across many lines or reconstructed through several functions, and it can miss unconventional patterns or flag safe-looking code that isn't. Treat findings as a fast first pass to guide manual review, not a verdict.
